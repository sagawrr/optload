The library

One intake.
Four precise packages.

Compose the image path your product needs. Start in the browser for speed and privacy, keep your server as the authority, and make every decision visible to your code.

01 · packages

Small surfaces.
Clear boundaries.

Each package does one job well. Use one, or wire the complete route from inspection to server verification.

@optload/core

Read image headers from bounded bytes, enforce upload policy, and return tagged errors before a decoder runs.

RuntimeAny JSSize~6 kB

@optload/browser

Normalize ordinary still images in a fresh worker. Promise-first APIs keep the happy path simple; Effect is there when you need it.

RuntimeBrowser workerSize~18 kB

@optload/server

Orchestrate deadlines, fallback routes, and output re-inspection across a declared process or service boundary.

RuntimeNode / EdgeSize~12 kB

@optload/sharp-normalizer

Reference Sharp/libvips adapter with one child process per image and an explicit buffer-loader allowlist.

RuntimeNodeSize~45 kB

03 · the first five minutes

Install, process,
handle the route.

TypeScript
import { createImageIntake } from '@optload/browser'

const images = createImageIntake({
  output: { format: 'webp', maxWidth: 2048 },
  fallback: async ({ file, reason }) => uploadToServer(file, reason),
})

const result = await images.process(file)

if (result.kind === 'local') save(result.blob)
if (result.kind === 'fallback') showServerRoute(result.value)
// reject is typed, early, and never uploaded automatically
