The library

The image intake stack.

Explore all packages

Four focused packages. One explicit path from hostile bytes to a verified output.

01 · inspect

@optload/core

Byte-level detection, policy, and tagged errors. Runtime-agnostic and deliberately boring.

02 · transform

@optload/browser

Fast, isolated normalization in a fresh worker. Promise-first with an Effect-native entry point.

03 · route

@optload/server

Explicit fallback orchestration for unsupported formats, deadlines, and output re-inspection.

04 · normalize

@optload/sharp-normalizer

Process-isolated Sharp/libvips adapter for reliable server-side decode and encode.

Developer first, by default

One intake.
Four precise outcomes.

The API stays small while the trust boundary stays visible. Choose a policy, process a file, and handle the result your way.

Read the package docs
TypeScript
import { createImageIntake } from '@optload/browser'

const intake = createImageIntake({
  output: { format: 'webp', maxWidth: 2048 },
  fallback: async ({ file, reason }) => uploadToServer(file, reason),
})

const result = await intake.process(file)
// local | fallback | reject

No hidden path

Three outcomes. Clear every time.

Read the security model

Local

Supported and safe? Process in a fresh worker and return the smaller blob.

Fallback

Missing a codec? Hand the original to your server with the reason attached.

Reject

Active, animated, or over policy? Stop before a decoder ever runs.
