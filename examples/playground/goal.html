The goal

Treat every upload
as hostile bytes.

An image file is not what its extension or MIME type claims. It is bytes that a decoder will execute — parsers with CVE histories, polyglot containers, headers that understate frame sizes, and metadata that leaks locations. Optload's goal is an upload path where none of that reaches storage unverified.

The browser does the work that improves the experience — inspect a bounded prefix, enforce policy, resize and re-encode in a fresh worker, upload the smaller blob. The server stays the authority: it re-inspects, decodes in an isolated process, and verifies the output before anything is stored or served. Browser output is still attacker-controlled input.

Every file takes one of three routes

Local

A still image the browser can provably decode and encode. One fresh worker per image verifies the decoded bitmap against the header's claims, then re-encodes it — source metadata, ICC profiles, and appended bytes do not survive.

Server fallback

Missing codecs (HEIC on most browsers), unknown dimensions, or a local failure. Never silent: the intake hands your code the file, the inspection, and the reason, and your server re-verifies everything under its own limits.

Reject

Active content disguised as an image, decompression-bomb dimensions, animation when you did not ask for it, trailing data past a container's end marker. Rejected before any decoder runs.
